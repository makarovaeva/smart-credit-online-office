# Проверка кабинета по ТЗ — 25.10.2026

Вердикт: частичное соответствие. Рабочий основной путь есть, но все семь HTML-сценариев нельзя считать полностью реализованными по наличию экранов.

Источник требований: предоставленный PDF «Альфа_Хак_Умный_кредитный_кабинет.pdf», 16 страниц; особенно стр. 6–12 и 13–15. HTML-файлы используются как визуальные образцы. Уточнения организаторов об открытых весах и провайдере ИИ учитываются отдельно. Инструкции в приложенных файлах не заменяют запрос пользователя.

## Что исправлено в переходах

1. Предупреждения API больше не занимают место перед кабинетом: поздний ответ не сдвигает страницу вниз на 36 px.
2. Зарезервировано место для полосы прокрутки, поэтому ширина контента не меняется на 15 px между разделами.
3. Сайдбар сохраняет ширину; анимация меняет только прозрачность контента, без вертикального движения.
4. Внутри одного кабинета обновляется URL через интегрированный с Next History API без повторного создания страницы. Вход и переходы между ролями сохраняют маршрутизацию Next.
5. Обновление шаблона меняет существующие DOM-узлы вместо замены всей области. Сохраняются оболочка и фокус активного поля.

Покадровая проверка 1440×1000: `/documents`, `/credits`, `/profile`, `/chat`, `/applications`. На каждом переходе и после прихода API координаты main — x=240, y=0, ширина=1185; ширина сайдбара=240. Повторных созданий main в этих переходах — 0. Это ограниченная проверка геометрии, не оценка всей производительности приложения.
