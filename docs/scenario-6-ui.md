# Сценарий 6 — Андеррайтер

> Исторический отчёт переноса HTML. Текущие маршруты и подключение API описаны в [frontend-api-status.md](frontend-api-status.md). Упомянутые ниже .dc.html — внутренние имена эталонных экранов.


Источник: предоставленный командой `Сценарий 6 · Андеррайтер.html`.
Перенесены 10 экранов с исходными текстами, CSS и размерами.
Клиентские сценарии и рабочее место аналитика не изменены.

чтобы не открывать вход аналитика. Внешний вид и текст ссылки сохранены.

## Проверки

10 из 10 скриншотов совпали попиксельно с исходным HTML в одном Chrome при
viewport 1440×720 и 1440×1000. Пройден 21 переход кликами мыши по видимым
элементам: вход, вкладки, запрос документов, отмена, запрос экспертизы,
подтверждение одобрения, контр-предложение, подтверждение отказа, закрытие окна,
выход и повторный вход. Автоматические решения не добавлены.

Повторение:

1. `python frontend/scripts/import-prototype.py <html> --scenario 6 --references frontend/.qa/scenario6-reference`
2. Отдельный headless Chrome с портом 9223 и отдельным профилем.
3. `node frontend/scripts/check-scenario.mjs 6`.

Артефакты: игнорируемая `frontend/.qa/scenario6-qa`.

## Интеграция ещё не выполнена

UI не вызывает backend. Демо-вход и кнопки отправки выполняют только переходы
HTML. Решение, комментарии, изменённые условия и запросы не сохраняются и не
меняют заявку клиента. «Напомнить аналитику» и «Отозвать запрос» не имеют
обработчиков в исходнике; поведение для них не придумано.

Следующий этап интеграции — серверная авторизация сотрудника, загрузка очереди
и карточки, назначение, отправка решения и запросов с проверкой прав и статуса
заявки в backend. Клиентский и сотруднический UI сейчас не связаны общими данными.
