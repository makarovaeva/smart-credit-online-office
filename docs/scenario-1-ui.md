# Сценарий 1 — Автоотказ ИИ: клиентский UI

> Исторический отчёт переноса HTML. Текущие маршруты и подключение API описаны в [frontend-api-status.md](frontend-api-status.md). Упомянутые ниже .dc.html — внутренние имена эталонных экранов.


Источник: предоставленный командой `Сценарий 1 · Автоотказ ИИ.html`.
Перенесены только исходные экраны, CSS, тексты, фиксированные значения и ссылки.
Главная, вход и короткие адреса теперь открывают сценарий 1.
Сценарии 2–4 сохранены по своим прежним именам; их реализация в этой задаче не менялась.

## Как посмотреть

Запустить `npm run dev` из `frontend/`. Начало: http://localhost:3000/login.

| Экран | URL |
|---|---|
| Вход | `/S1_Login.dc.html` |
| Главная без заявки | `/S1_HomeEmpty.dc.html` |
| Подтверждение параметров | `/S1_Chat.dc.html` |
| Изменение параметров | `/S1_ChatEdit.dc.html` |
| Документы и скоринг | `/S1_ChatSubmitted.dc.html` |
| Главная после подачи | `/S1_HomeSubmitted.dc.html` |
| Автоотказ в чате | `/S1_ChatAutoDecline.dc.html` |
| Главная после автоотказа | `/S1_HomeAutoDecline.dc.html` |
| Документы | `/S1_Docs.dc.html` |
| Кредиты | `/S1_Credits.dc.html` |
| Профиль компании | `/S1_Profile.dc.html` |

Проверенная цепочка кликов: «Получить код» → «Подать заявку в чате» →
«Изменить» → «Сохранить изменения» → подтверждение заявки →
«К заявке на главной» → автоматическая смена статуса → «Спросить ИИ-агента» →
«Подать новую заявку». Переходы воспроизводят ссылки исходника.

## Визуальная проверка

24.10.2026: все 11 экранов сравнены с оригинальными HTML в одном headless Chrome,
с viewport 1440×720 / 1440×1000 / 1440×1200 по размеру исходного фрейма.
PNG-сравнение через Pillow: 11 из 11 совпадают попиксельно.
После уточнения пользователя служебная ссылка «Обновить статус» удалена:
в UI-демо главная и чат проверки автоматически показывают отказ через 8 секунд.
При повторном сравнении эта ссылка исключается из эталона; остальная вёрстка сохраняется.
Также проверены 10 последовательных переходов реальными кликами по ссылкам.
Нативная таблица согласий восстанавливается из экспортных `sc-raw-*` тегов.

Повторение проверки:

1. `python frontend/scripts/import-prototype.py <html> --scenario 1 --references frontend/.qa/scenario1-reference`
2. Запустить отдельный Chrome с `--headless --remote-debugging-port=9223 --hide-scrollbars`
   и отдельным `--user-data-dir`, не основным профилем пользователя.
3. `node frontend/scripts/check-scenario.mjs 1`

Снимки и отчёты создаются в игнорируемой `frontend/.qa/scenario1-qa`.

## Границы текущего этапа

Это точный UI-прототип. SMS, чат с моделью, реальные файлы и сохранение заявки
не подключены. В исходнике «Сохранить изменения» — ссылка на статический экран,
поэтому изменённые значения пока не сохраняются. Кнопки «Отправить», «Скачать»,
«Детали заявки», «Уточнить причину», «Что можно исправить» не имеют обработчиков
в HTML; дополнительные окна и ответы для них не придуманы.

Текст про SMS, плейсхолдеры причин отказа и данных компании оставлены как в макете.
Расхождения с backend перечислены отдельно в `frontend-backend-gaps.md`.
Адаптивная переработка не выполнялась: размеры и поведение сохранены по HTML.
