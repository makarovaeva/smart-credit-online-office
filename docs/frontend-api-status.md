# Frontend: маршруты и подключение API

## Адреса

| Раздел | URL |
|---|---|
| Вход клиента | `/login` |
| Заявки / актуальное состояние | `/applications` |
| Параметры заявки / чат | `/chat` |
| Документы | `/documents` |
| Кредиты | `/credits` |
| Профиль компании | `/profile` |
| Вход аналитика | `/staff/login?role=analyst` |
| Аналитик | `/staff/analyst` |
| Вход андеррайтера | `/staff/login?role=underwriter` |
| Андеррайтер | `/staff/underwriter` |
| Вход администратора | `/staff/login?role=admin` |
| Администратор | `/staff/admin` |
| Карточка администратора | `/staff/admin/applications/{application UUID}` |

Ссылки `.dc.html` остаются внутренними именами эталонных экранов. При открытии
старой ссылки браузер нормализует адрес; ссылки в интерфейсе уже ведут на новые URL.
Вкладки и модальные окна — React-состояния, а не отдельные HTML-файлы в URL.
Назад/вперёд работают через History API. SessionStorage хранит только выбранный
ID заявки и состояние интерфейса, не JWT и не копию банковских данных.

## Подключено

- Вход клиента по телефону и сотрудников по email/паролю, `/me`, выход.
- HttpOnly cookie сессии. Запросы браузера идут в Next BFF `/api/session`
  и `/api/backend/*`; Next передаёт Bearer-токен в FastAPI. Изменяющие запросы
  проверяют Origin. Используется серверный `API_URL` из `frontend/.env.example`.
- Каталог продуктов, выбор подходящего продукта по цели, сумме и сроку.
- Создание черновика, изменение суммы/срока с `version`, согласия после явного
  подтверждения пользователя, подача заявки.
- Реальный статус и `available_actions`; опрос раз в 5 секунд, без демотаймеров.
  Во время ввода и операций опрос приостанавливается, чтобы не терять данные формы.
- Оффер и контр-предложение, принятие и отклонение, смоделированное подписание
  и выдача по существующим backend-командам, договор и реальный график платежей.
- Реальные очереди сотрудников и администратора, выбор заявки по UUID, карточка,
  скоринг, журнал из `history`, счётчики по загруженным данным.
- Заключение аналитика и рекомендация; решения андеррайтера: одобрение,
  контр-предложение, отказ, запрос документов и экспертизы через `/decision`.
- Документы: загрузка (multipart через прокси), список и скачивание, ответ клиента
  на дозапрос. Запрос документов аналитиком через ИИ-агента
  («Передать ИИ-агенту» → `POST /backoffice/applications/{id}/info-requests`).

Решения и права остаются на backend. UI не «дожидается» заранее заданного отказа
или одобрения, а показывает возвращённое состояние. Согласия `bki`, `fns`,
`digital_profile` отправляются только после подтверждения пользователя.

## Не готово из-за backend / контрактов

- История и отправка сообщений чата: endpoint отсутствует. Синтетические сообщения
  HTML удалены из рабочего чата; вместо них показана недоступность помощника.
- Принятие/возврат экспертизы, напоминания и отзыв
  запроса не имеют согласованных команд. UI не выдаёт успешные демопереходы.
- Отдельные PDF/XLSX-экспорты и файлы согласий не предоставлены. Договор и график
  доступны как реальные данные; кнопки отсутствующих экспортов не создают фиктивный файл.
- Контракт очереди пока не позволяет надёжно различать новую эскалацию и запрос
  андеррайтера без дополнительных данных; соответствующие вкладки используют
  доступные статусы. Точный scope и счётчики нуждаются в согласовании команды.
- Форма залога в макете недостаточна для всех обязательных реквизитов backend;
  новая клиентская заявка в этом этапе поддерживает вариант без залога.

Полный список для backend-команды: `backend-integration-requests.md`.
Эта команда отвечает за недостающие методы; frontend-разработчику не требуется
переписывать существующий backend.

## Проверено на локальной синтетической БД

`frontend/scripts/check-connected.mjs` запускается при работающих backend,
frontend и отдельном headless Chrome с портом отладки 9223.
Скрипт **создаёт синтетические заявки**; не запускать на производственных данных.

- Входы клиента, аналитика, андеррайтера и администратора через UI.
- Создание/согласия/подача → очередь назначенного андеррайтера → одобрение через UI.
- Повторный вход клиента → принятие оффера → подпись → `completed` в API.
- Реальный договор и 24 платежа, отображённые в таблице.
- Автоотказ по демо-клиенту с номером `+7 999 000-00-03`.
- Эскалация клиента `+7 999 000-00-04` → аналитик запрашивает выписку через UI →
  клиент загружает файл и отвечает → заявка снова у аналитика, файл скачивается →
  сохранённое заключение аналитика → андеррайтер.
- Администратор видит ту же заявку и историю после перезагрузки; возврат браузером.
- В ссылках нет `.dc.html`, JWT недоступен через `document.cookie`.
- Профиль компании из `/companies/{id}`: реквизиты, ОКВЭД, налогообложение, руководитель, бенефициары, право подписи, контакты и расчётный счёт.
- Раздел «Документы» показывает список из API (у заявки без файлов — «Документов нет»).
- TypeScript и production build проходят.

Отчёт и скриншот — в игнорируемой `frontend/.qa/connected`.
Отчёты `scenario-N-ui.md` фиксируют историческую проверку вёрстки по HTML;
они не являются доказательством текущей банковской интеграции.
